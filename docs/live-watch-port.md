# BiliLive Watch 原生移植與驗證

移植於 2026-11-08 完成。目前 Windows x64 可攜版為 [BiliNook.exe](../dist/BiliNook.exe)。

## 已實作

四個主入口維持動態、投稿影片、直播工作台、設定與 UP 管理。直播工作台包含卡片／清單、七種房間狀態、搜尋標示、進階篩選與預設、房號／短號／網址及批次新增、置頂、備註、獨立分組、拖曳與鍵盤排序、批次移動／移除與復原、觀看清單、觀測統計、歷史及 CSV、通知紀錄與勿擾。

觀看清單可建立、編輯、複製、調整房間順序、限定目前清單範圍及保存同屏。已離線或移出監看的房號仍保留在清單中。播放器支援卡片預覽、自適應／四宮格／九宮格／焦點版面、1／2／4／9 間上限、官方彈幕及全螢幕。焦點版面保留其他房間的小播放器。

主題、重點色、已安裝字體、字體與卡片縮放、密度為全程式設定。內容縮放允許 0.5–2 倍；導覽與工具列限制在 0.85–1.2 倍，以免最大字級的窄視窗只剩控制列。首次移轉維持目前外觀，另提供帶入舊直播外觀後儲存的操作。

動效以 GPUI 重作，包含可中斷的 220ms 數值／卡片重排、260ms 抽屜進出、原生分段選取、狀態呼吸圓點與指標按下波紋。只計算可見卡片；減少動效或鍵盤操作直接到位。原始 CSS 材質及瀏覽器元件的每個 spring 屬性不保證逐像素一致。

## 架構及相容

- `bili-core/src/live_watch/`：相容模型、驗證／合併、房間與來源關聯、觀測、通知、查詢快取及背景協調器。
- `JsonStore`：同一存檔 actor、獨立 `live-watch.json`、原子替換與跨檔 journal；一般追蹤快照不複製直播歷史。
- `bili-gpui/src/app/live/`：工作台、抽屜、統計與表單；`motion.rs` 負責共享動效與可見位置快取。
- `player.rs`：STA 主執行緒建立的 `wry 0.57.1`／`webview2-com 0.39` 子視窗。官方網址明確帶 `autoplay=1`。共用獨立 WebView2 profile，沒有把官方頁面當作應用程式介面。

GPUI 使用其 DXGI HWND 硬體加速路徑。預設 DirectComposition 的上層 target 會蓋住 WebView2 子視窗，因此程式在任何執行緒啟動前設定 `GPUI_DISABLE_DIRECT_COMPOSITION=1`；沒有修改套件快取或系統設定。

自動追蹤與手動房間依正式房號合併。取消自動房間只保存直播排除；手動房間在移除 UP 後仍保留。網路回應只更新觀測資訊，房間編輯由 actor 提交，舊回應及已移除房間不會復活。

首次沒有直播檔時唯讀載入 `BILILIVE_DATA_FILE`，否則讀取 `%USERPROFILE%\.bililive-watch\rooms.json`。先驗證再寫新檔；有損壞資料時保存錯誤，可重試、手動匯入或略過。重啟不重複移轉。舊瀏覽器 localStorage 的通知、勿擾與操作音效偏好未存入來源 JSON，使用新預設。

整合備份為 v3，含可選的 `liveWatch`；舊備份缺此區塊時保留直播資料。另有來源 JSON v1／v2 合併／覆蓋及 v2 匯出。未知追蹤欄位及原有資料檔格式保留。覆蓋匯入在介面要求再次確認。

可靠觀測遇查詢失敗或程序中斷時停在最後可靠時間；不跨失敗區間推估。每房保留最近 50 場觀測，未知時長為空值。日期查詢使用裝置當地日期及區間交集。CSV 有 BOM、CRLF、引號跳脫及公式防護。

通知由核心判斷；首次載入、新增、錯誤恢復不提醒。保存最近 100 筆，支援已讀、清空、暫停一小時、跨午夜勿擾、單房開關及音量。直播通知以房號導向程式內定位，編輯中的抽屜關閉後才套用定位。

## 實際驗證

`cargo check --workspace --offline` 通過。完整 workspace 78 項通過，另新增直播／追蹤跨檔中斷復原案例通過，合計 79 項：核心單元 8、原有契約 26、動態／服務 7、直播契約 19、原生程式 19。後續播放器重試及全螢幕修正再跑對應 19 項原生測試，全部通過，沒有降低原有測試標準。

直播契約涵蓋安全房號解析、七態、去重、手動／UP 關聯與排除、復原、長備註、損壞歷史拒絕、合併優先序、通知／勿擾、觀測中斷及舊回應、CSV／跨日區間、正式房號合併、排序衝突、觀看清單穩定 ID 與移除房間保留、並行存檔、舊整合備份、首次移轉及重試、快取合併查詢、直播與追蹤檔同時損壞時由 journal 一起復原。

Windows 原生 UI Automation 與實際截圖已驗證：

- 全新隔離目錄自動帶入 22 間房、2 個分組；來源房間檔保持原樣。
- 明亮／暗黑、約 900×650 邏輯大小的窄視窗、一般及全螢幕視窗、字體／卡片 0.5 倍與 2 倍，以及大字級下的導覽修正。
- Ctrl+K、房號查找、Enter 啟用、分組新增落盤、保存目前同屏清單。
- 批次新增將既有房間回報為已存在；外站網址與 0 明確失敗；失敗項目可再次重試。
- 真實官方四房及九房影像、720p／1080p 媒體狀態、時間前進、非靜音音軌與彈幕。未以人耳或音訊回錄確認每一條音軌。
- 九房抽屜遮擋與恢復、焦點版面、全螢幕及 Escape；全螢幕內 Ctrl+K 的抽屜在播放區之上，切入統計恢復正常視窗並釋放播放。
- 隱藏至托盤後單房播放時間從 3.9 秒進至 9 秒；第二程序退出碼 0 並喚醒原程序。切到影片後無障礙樹中的播放器文件降為 0，安全退出成功。
- 以程序專用的空 Runtime 路徑模擬 WebView2 不可用，出現「重試」「WebView2 安裝說明」，仍可切至影片並退出；沒有卸載或變更系統 Runtime。

實際顯示器為 150% DPI；另向隔離視窗送出 96／192 DPI 的 `WM_DPICHANGED`，檢視 100%／200% 版面、播放器尺寸與底部裁切，再復原 144 DPI。這是同視窗轉換測試，不能當作兩台真實不同 DPI 螢幕間拖曳的證明。減少動效使用 debug 程序覆寫，未改動使用者的 Windows 設定。

主要證據在 `.local/live-port/`：`four-playing.png`、`nine-confirmed.png`、`nine-covered.png`、`focus-layout.png`、`fullscreen.png`、`fullscreen-drawer.png`、`fullscreen-to-stats.png`、`batch-verified.png`、`light-saved.png`、`scale-min-final.png`、`scale-max-fixed.png`、`dpi-100.png`、`dpi-200.png`、`runtime-fallback.png`、`release-playing.png`。截圖可能包含測試當時的公開直播內容。

## 本機效能與限制

Release 四房真實串流狀態取樣 5.9 秒，在 20 邏輯處理器主機上，程式與 WebView2 子程序合計 13 個程序：CPU 約佔全機 9.33%，加總 working set 1465.3 MiB、private bytes 977.1 MiB。working set 可能重複計入共享頁面，不能等同獨佔實體 RAM。測試程序另以 Chromium 的程序參數靜音輸出，沒有改使用者的音量設定。原始數值在 `performance.json`。

九房切換／載入期間觀察到掉幀增加。這次沒有取得整段原生 UI 的幀時間分佈，也沒有建立通用 FPS 保證；只記錄實際影像、媒體旗標、操作結果及上述資源快照。尚未驗證其他機器、所有網路／登入／地區限制、長時間常駐與真實跨螢幕 DPI。

播放器需要 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)。B 站的官方播放器或公開 API 若改版、風控、區域限制或房間下播，仍可能載入失敗；可重試或開啟官方直播間。
