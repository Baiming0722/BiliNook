## 2026-11-08 播放器建立時的閃退修復

真實滑鼠點擊未開播房間時，已重現 Wry 建立 WebView2 同步處理 Windows 訊息，引起 GPUI App 可變借用重入並 panic。`PlayerHost` 將建立請求序列化，實際建立在 GPUI App／播放器狀態借用結束後執行；收合、切頁與退出會取消待建立項目，退出會等待正在建立的子視窗返回。使用真實滑鼠事件、隔離資料測試兩個未開播房間、快速收合重開、切頁及退出；另實測直播與同屏播放。Workspace 92 項測試通過。先前按壓波紋修復只是另一個問題，不能視為本次重入問題已解決。

## 前次更新：分組載入與 ASCII 對齊

`FeedService` 對首頁空回應重試一次；若仍為空且有舊資料則保留舊內容及警告，空清單快取縮短至 5 秒。分頁失敗保留已取得內容並中止不安全的後續游標。分組或篩選範圍變動時先切換載入狀態。側欄吉祥物以共同等寬座標繪製，新增 Pong 載入及分頁／分組擦拭。91 項 workspace 測試通過，隔離視窗已實際載入組別公開動態並檢視畫面；詳見 [使用及驗證](ascii-ui.md)。

## 前次更新：圖文動態修復與 ASCII 介面動畫

`api/parse.rs` 依實際 `major` 主體而非優先依外層類型選擇圖文格式，並解析可選預約資訊；`DynamicItem.reservation` 預設為空，沒有變更追蹤資料存檔。圖文、減少動效和關閉選項的隔離測試與當時 86 項 workspace 測試見 [使用及驗證](ascii-ui.md)。最初因 API 回傳空清單無法驗證截圖指定的動態，後續隔離實測已取得該動態。

## 前次更新：直播預覽修復與 ASCII 狀態擴充

`motion.rs` 的按壓事件現在用 `window.refresh()` 啟動重繪，僅在 canvas 繪製時要求後續動畫影格；修正預覽與新增監看按鈕因 GPUI 階段錯誤而 panic。`ascii.rs` 增加載入連線軌道及直播廣播符號，並沿用既有偏好、共同時鐘和減少動效。隔離測試、真實公開直播及 workspace 84 項測試結果見 [ASCII 使用及驗證](ascii-ui.md)。

## 前次更新：技能輔助的小型 ASCII 狀態動畫

目前合計 84 項測試通過。參考使用者指定的 ascii-skills，增加等待三點、五字元處理軌道、動態／投稿初次載入提示及批次真實進度；保留單字元轉圈，合計 21 處動畫及一處進度條。實作在 `crates/bili-gpui/src/ascii.rs`，沿用既有 120ms 節奏，24 步為共同週期；三點與處理軌道每兩步換幀。沒有新增依賴、計時器或持久化欄位。批次輸入改為 4–6 行自動高度及內部捲動，修正十行輸入蓋住控制列。`appearance.asciiAnimationEnabled` 及整合備份相容性保留。詳見 [使用及驗證](ascii-ui.md) 與 [設計規格](ascii-design.md)。

完整 workspace 78 項通過，另新增跨檔復原案例通過，合計 79 項。核心直播模組在 `crates/bili-core/src/live_watch/`，原生工作台在 `crates/bili-gpui/src/app/live/`，播放器為 `player.rs`。Windows 限定依賴 `wry 0.57.1`／`webview2-com 0.39`，僅使用於官方直播播放器。保留啟動前的 `GPUI_DISABLE_DIRECT_COMPOSITION=1`，以免 GPUI 上層 target 蓋住子視窗；仍為 Direct3D 硬體加速。

已完成的檢查在沒有新變更或錯誤時不必重跑。成品未簽署；真實跨螢幕 DPI、其他電腦與長期常駐尚未驗證。播放需要 WebView2 Runtime，缺失時監看及其餘頁面仍可使用。

1. 執行 `scripts/build-release.ps1` 產生 `dist/BiliNook.exe`。
2. 以 `--data-dir <本專案>/.local/release-validation` 啟動成品；禁止直接不帶參數啟動進行測試，release 預設為正式共用資料。
3. `.local/verification/release-probe.ps1` 已準備好：用原生 UI 操作 X 隱藏、第二實例喚醒、從隔離備份取得一個既有 UID，透過 UI 加入追蹤。需傳入成品程序 PID。腳本執行前需先啟動成品。

## 執行環境與路徑

- Rust 1.99.1 MSVC；MSVC 14.44.35207／Windows SDK 10.0.26100.0 已可建置。
- `gpui` 匯入名稱實為 `gpui-kit = 0.9.0`，內含 Component 0.9.0／GPUI-pre 0.3.11。不能改用舊 crates.io gpui 0.2.2 混搭。
- `bili-core` 不依賴 GPUI，擁有 Tokio Runtime；GPUI 透過有界 channel 等待結果。UI 工作可取消，已接受的存檔由 actor 持有並在退出時 flush。
- `scripts/cargo.ps1` 自動使用專案 `.cargo-home`；PowerShell 請停用 profile（`login:false`），避免 oh-my-posh 錯誤。Cargo 與原生 UI 自動化通常需要工具的 `require_escalated`（已獲自動審查允許）。
- 初次 release 腳本一度被 Windows 拒絕執行；未改權限，改 `CARGO_BUILD_JOBS=2` 重試即成功。
- 舊專案唯讀：`C:\Users\USER\Desktop\Files\web\bilibili-follow`；正式資料唯讀測試來源：`C:\Users\USER\.bilibili-follow\data`。
- 開發測試副本 `.local/legacy-sample` 有 8 位 UP／2 分組。`.local/verification/gui-backup.json` 為原生 UI 匯出的可還原備份。
- `scripts/capture-window.ps1` 以 PrintWindow 擷取應用程式的 HWND；`scripts/ui-probe.ps1` 支援原生按鈕 Invoke／Input／Resize／Close。Start-Process 請加 `-WindowStyle Hidden`，取得 HWND 時用 FindWindow('Zed::Window','BiliNook')，Hidden 啟動時 MainWindowHandle 可能為 0。
- `dist/使用說明.md` 與 README 已說明 release 預設共用正式資料、切換前先退出舊版、獨立試用參數、資料及功能界線。成品未簽署。
